SpelaionDB 0.16.0 compares and copies databases. Compare two schemas and get a report of what
differs, object by object, with the script that makes one like the other opened in the editor,
never run from the comparison. Copy tables from one connection to another, across engines, with
the columns mapped, the statements shown before anything runs, and binary columns carried as
bytes. The guard also reads comments as each engine does now, so a nested comment can no longer
hide a destructive statement.

## Compare schemas
- **From a schema's menu in the explorer:** pick the target connection and schema, and the core
  reads both catalogs in sessions of their own, for reads only, so the explorer stays usable and
  a cancel stops them (ADR-070).
- **A report per object:** tables, columns, keys, constraints, indexes, views and routines, each
  marked changed, only in the source or only in the target, with what differs in each part.
  A view's or routine's source is compared without counting runs of blanks between tokens, and
  its own-schema qualifiers as the same.
- **The script that makes the target like the source** opens in a new editor tab on the target
  connection, with what cannot be undone and what was not compared written at its top. Nothing
  runs from the comparison; dropping what only the target has is a choice you make.
- PostgreSQL, MySQL, MariaDB, SQL Server, SQLite and DuckDB, between two connections of the same
  engine. On other engines the action says why it is not available.

## Copy tables between connections
- **From a table's menu in the explorer**, into a schema of any other connection: structure and
  data, structure only, or data only into a table that is there (ADR-069).
- **The columns are mapped across engines** and shown before anything runs: each source type,
  the type it becomes, and what changes. The `CREATE TABLE` and the insert are shown as they will
  run; values travel as parameters or the engine's bulk data, never written into the SQL.
- **Columns, nullability and the primary key** are copied; indexes, foreign keys, defaults,
  checks and triggers are not, and the review says how many of each were left out.
- **Binary columns travel as their bytes** on every pair of the SQL engines we ship, through
  plugin protocol 1.3. Babelfish still refuses them.
- The source is read a batch at a time inside its engine's read barrier, never the whole table in
  memory; the load goes through the target's safeguards, as an import does. A copy into the same
  SQLite or DuckDB file is refused up front, with a way to do it in that connection's console.

## Safety
- **The guard reads comments as the engine does.** On PostgreSQL, DuckDB and ClickHouse a
  `DELETE`, `UPDATE`, `TRUNCATE` or, on DuckDB, a `DROP` after a nested block comment
  (`/* a /* b */ c */`) went unasked; on Trino, Databend and Flight SQL a `DROP` that was not the
  first statement asked when it should not, and `#` was taken for a comment where the engine has
  none. The guard now reads every statement through its dialect's own scanner.
- **Idle transactions can be rolled back.** A connection type can set
  `close_idle_transaction_after`: an editor tab whose transaction stays open and unused that long
  is warned a minute before, then rolled back, and the tab says how many statements were undone.
  A session in use is never touched, and nothing re-runs (ADR-081).
- **A cancelled SQL Server statement no longer breaks its session.** Cancelling a batch that had
  begun or ended a transaction could leave every later request failing with error 3989; the
  plugin now keeps the transaction state right, or reports the session lost.

## Engines
- **Materialize:** sinks, connections, secrets, clusters and cluster replicas in the explorer,
  with their definitions (a secret's value is never read) (ADR-082).
- **ClickHouse:** the import dialog says the import is kept whole, instead of offering "Commit
  every", which does not apply there.
- **SQL Server LocalDB** stays without TLS on its pipe: LocalDB offers none, so nothing can be
  done from the client. A connection that asks for encryption fails, and is never sent in plain
  text. ADR-068 now gives the real reason.

## Under the hood
- PostgreSQL's splitter, code ranges and COPY reader read text through one lexical scanner
  (ADR-065), compared with the old reader on a million cases per input; property tests now check
  that every reader of each dialect agrees with its splitter.
- Plugin protocol 1.3: Materialize's object kinds, and byte columns in `insert_rows`.
- `spelaion-plugin-fetch --platform` names a plugin's program as on the platform it fetches for.
- A smoke test step that read the grid once now waits for it.

## Plugins
- PostgreSQL 0.1.6 and 0.1.7: Materialize's objects, and bytes in copies.
- MySQL 0.1.8, DuckDB 0.1.3 and ClickHouse 0.1.3: bytes in copies.
- SQL Server 0.1.3 and 0.1.4: the session stays usable after a cancel, and bytes in copies.
