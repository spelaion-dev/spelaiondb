SpelaionDB 0.12.0 is about the work around the queries: files in the formats other tools read,
the maintenance a database needs, tables that tell everything the catalog knows about them, and
connections that go through poolers and bastions safely.

## Exports and imports
- **More formats.** Export results, a table data tab or explorer tables to Parquet, Arrow and
  NDJSON, optionally gzipped, with file name patterns. SQL exports can write upserts in each
  engine's own syntax, and JSON exports have their own options.
- **Excel in and out.** Export to an Excel workbook, written a sheet at a time. Dates are real
  dates (including MySQL's and SQL Server's), with milliseconds, and date and boolean columns
  are sized to fit. Import one sheet of a workbook, chosen in the import dialog's options; the
  file is read as untrusted input.
- The export dialog opens with the last export's format and options.

## The explorer
- **Everything about a table.** A table's properties, partitions (a node for each) and
  dependencies, in the explorer and in the table details. The structure form edits a table's
  comment. SQLite tells all of it today. The other engines tell it once their plugins have been
  updated: until then they say they do not tell dependencies yet.
- **Maintenance actions:** VACUUM, ANALYZE, refreshing materialized views, TRUNCATE's options,
  CHECK, REPAIR and OPTIMIZE, rebuilding indexes, and turning triggers on and off, each as its
  engine has it.
- SQLite tables show their CHECK constraints, named or not, in the explorer and the table
  details.
- **Duplicate a table**, its structure only or with its rows. The dialog says what the copy keeps.
- A saved connection of a kind (CockroachDB, TiDB, Valkey…) or a folder of CSV and Parquet files
  keeps its own mark in the explorer and the process monitor, instead of its base engine's.

## Connections
- **Connection safety.** A warning when TLS does not check the server's certificate,
  Disconnect all, Reconnect, and read-only for this session.
- **Poolers and bastions:**
  - a PgBouncer mode on PostgreSQL connections, where transaction mode relies on no session
    state;
  - MySQL's and MariaDB's cleartext password plugin, sent only over TLS that checks the server
    or through an SSH tunnel;
  - the databases a connection shows, for MySQL, MariaDB and SQL Server.
- **The connection test runs the session setup** too (its own step), so a setup statement that
  fails is found before saving, not at the first connection.
- A script refused on a session made read-only says "this session is read-only", not the
  connection.
- **Open from outside the app:** a folder, an `.sql` file or a connection. Recent folders are
  listed.
- Importing connections no longer offers to store passwords when the import has none, and the
  importers are grouped in one "Import from another client…" menu.
- A tab opened from the explorer after you edit and save a connection uses the saved connection.
  If the login changed, it asks to connect again.

## Agents
- **Read-only agents on one connection.** The MCP page's Security tab makes agents read-only on
  a single connection, kept on this computer. A running `spelaiondb mcp` checks it before every
  write and says so in `list_connections`; if the setting cannot be read, agents only read.

## Scripts
- **A plain `pg_dump` file runs.** The data after `COPY … FROM stdin` is loaded through
  PostgreSQL's COPY protocol, streamed, inside a transaction of its own. The guard, read-only
  mode and the history only see the statement, never its data. A dump's `\restrict` lines are
  skipped; any other psql command is refused with the reason.

## Results
- Select every loaded cell from the grid's corner.
- **Screen readers** hear the result grid's cell (its row, visible column and value) on every
  move, and its new value after an edit.
- **Cancel reaches more statements:** on PostgreSQL (plugin 0.1.3), MySQL and MariaDB (MySQL
  plugin 0.1.4), a cancel pressed right after Run stops the statement even before it reaches the
  server. On ClickHouse, a statement right after a capped read no longer finds the session
  locked (ClickHouse plugin 0.1.1).
- On MySQL and MariaDB, a statement with a backslash in a string no longer makes the session
  forget its database, so the results that follow can still be edited (MySQL plugin 0.1.5).
- A data search cancelled just as it ends shows how it ended, instead of staying at
  "Cancelling…".

## Plugins and diagnostics
- **Settings › Plugins** shows each running plugin's memory, processor use and sessions, and
  restarts one. A restart asks first only when one of the plugin's sessions has a transaction
  open.
- **Copy diagnostic info** for bug reports. A screen that fails shows a panel instead of a blank
  window.
- Plugin protocol 1.2 adds a table's details. Plugins that speak 1.0 or 1.1 keep working and are
  never asked for them.
