SpelaionDB 0.5.0 makes the explorer a database navigator: objects in folders by type, filters,
DDL and the SQL you would otherwise type by hand. It also tightens what AI agents may run.

## The explorer, by type
- **Folders by type** under each schema (ADR-024): tables (partitioned ones marked), foreign
  tables, views, materialized views, functions, procedures, aggregates, sequences, triggers, data
  types, events (MySQL, MariaDB) and synonyms (SQL Server), as each engine has them. Roles,
  users, logins, tablespaces and extensions follow the schemas.
- **Under a table:** its columns, constraints (primary key, unique, check), foreign keys and
  indexes.
- **System objects** (system schemas, built-in roles and logins) are hidden until Settings →
  Explorer shows them.
- **Sorting:** alphabetical and ignoring case by default; the database's order, case-sensitive
  order or folders first are in Settings → Explorer.
- **Refresh:** F5 on a table or schema reads it again; "Refresh all schemas" (a schema's menu,
  the connection's "⋯" menu or F5 on the connection) reads everything again, autocompletion
  included. What is expanded stays expanded.

## Filters
- **Quick filter:** the magnifying glass over the explorer, or Ctrl+Shift+F, keeps what matches
  a name.
- **Connection filters**, as in DBeaver: right-click a connection, a folder of objects or a
  table's columns, "Configure filter…", and include or exclude patterns (`*`, `?`). A filtered
  folder says so. Filters are yours: they are kept on this computer, not in the connection's
  file (ADR-025).
- **Hide / Show only** in the right-click menu, for one object or every one chosen with
  Ctrl+click.
- **Only the connected connections:** the plug over the explorer.
- **Big catalogs:** filters go into each engine's catalog query, so a server with thousands of
  schemas or tables only sends what passes them (Settings → Explorer → Use server-side filters).

## Generate SQL
In a table's right-click menu, written by the core with the engine's quoting and `:name`
placeholders; nothing runs until you run it.

- **DDL** of a table or view (and of functions, triggers, sequences, types and indexes): the
  engine's own text, or composed from the catalog for PostgreSQL and SQL Server, with
  constraints, indexes and comments.
- **SELECT by key** (`WHERE key =`) and by a list of keys (`WHERE key IN`). Without a primary
  key, SELECT by key, UPDATE and DELETE use a unique key.
- **Upsert** (`INSERT … ON CONFLICT`, or `ON DUPLICATE KEY UPDATE`) and **MERGE**, where the
  engine has them.
- **UPDATE … FROM** and **DELETE … USING** a source of values, in each engine's form.
- **JOIN** of the tables chosen with Ctrl+click, simple or INNER, on their foreign keys.
- **CALL** of a procedure, its outputs collected.

## AI agents
- Agents can no longer replace tables or schemas (`CREATE OR REPLACE`), and `ALTER TABLE` is
  limited to adding columns or constraints and renaming: dropping columns, changing their types
  or dropping partitions is refused.
- MySQL and MariaDB executable comments (`/*! … */`, `/*M! … */`) are refused for agents: the
  server runs what the parser takes for a comment.

## Fixes
- A `MERGE` written in the editor now runs on SQL Server: the statement splitter dropped the
  semicolon SQL Server requires.
- MariaDB's sequences are no longer listed as tables.

## Installing
- **Windows:** `SpelaionDB_0.5.0_x64-setup.exe` installs for the current user without admin
  rights; the `.msi` is there for managed machines. The installers are not signed yet, so
  SmartScreen may warn: "More info" → "Run anyway".
- **macOS:** the `.dmg` for Apple Silicon (`aarch64`) or Intel (`x64`). The app is not notarized
  yet: open it with right-click → Open the first time.
- **Linux:** `.deb`, `.rpm` or the AppImage. Only the AppImage updates itself.
- **CLI / MCP server:** the `spelaiondb-*` archives hold the `spelaiondb` binary.

0.4.0 updates itself to this version from the notice at the top of the window.
