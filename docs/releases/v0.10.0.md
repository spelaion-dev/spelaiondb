SpelaionDB 0.10.0 is about engines: every database except SQLite is now reached through a
plugin of its own, and that opened the door to many more. The app now reaches columnar and
distributed SQL engines, document, key-value and graph databases, search engines, time series
and Google Cloud Spanner. The plugins it uses are installed and updated from a signed catalogue, without waiting
for an app release.

## New engines
- **ClickHouse**, the first engine that only exists as a plugin, with a read-only mode the server
  enforces.
- **Oracle**, on Oracle's own thin driver: nothing to install. Cancel and TLS work through SSH
  tunnels.
- **Trino and Presto**, with catalogs, schemas and tables in the explorer.
- **Arrow Flight SQL**: any server that speaks it, plus **Dremio**, **GizmoSQL** and
  **InfluxDB 3**.
- **Hive, Spark, Kyuubi and Impala**, through one HiveServer2 plugin.
- **Databend** and **Google Cloud Spanner**, each over its own HTTP API.
- **libSQL / Turso**, typed and browsed as SQLite.
- **MongoDB and FerretDB**: write the shell's familiar calls (`db.orders.find({…})`), which the
  core reads and sends as commands. JavaScript is not run. A MongoDB Atlas `mongodb+srv` address
  works too: the core looks up its servers in DNS, and TLS is always on and checks them.
- **Redis and Valkey**: one command per line, as `redis-cli` writes it. The explorer browses keys
  one bounded page at a time and never runs `KEYS *`.
- **Cassandra and ScyllaDB**, with CQL split and guarded by the core.
- **Neo4j**, with Cypher. Nodes, relationships and paths arrive as JSON cells.
- **TDengine**, with its own SQL.
- **Elasticsearch, OpenSearch, Solr and Meilisearch**: write requests to the engine's own HTTP API
  (a method, a path and a JSON body), with highlighting and formatting. They only ever go to the
  connection's server, and an index opens with a bounded search.
- New kinds of PostgreSQL connection: **CockroachDB**, **YugabyteDB** and **TimescaleDB**.
- New kinds of MySQL connection: **TiDB**, **OceanBase**, **SingleStore** and **GreptimeDB**.
  GreptimeDB's rows are keyed by their primary key and time index, so a row can be deleted from
  the table data tab.
- **A folder of CSV, TSV and Parquet files** opens as a read-only DuckDB connection, with one
  view per file.

The new engines and kinds have no read-only mode and are not shown to agents until each has a
barrier its own server enforces and tests that try to get around it. The exceptions are
ClickHouse, Trino, Presto and the PostgreSQL and MySQL kinds whose server enforces read-only
transactions. On ClickHouse, Trino and Presto, agents can read but not write, and the MCP page and
`list_connections` say so.

## Plugins
- Settings has a **Plugins** page. It lists every plugin and the engines it serves, which build
  is in use and why a build is refused. It installs and updates our plugins from a catalogue we
  sign, or from an archive you pick. A newly installed build is used without restarting the
  app.
- The connection picker shows engines whose plugin is not installed yet, and a connection whose
  plugin is missing says so and links to the page.
- The core starts only the builds this release pins or the signed catalogue names, and checks
  each program's SHA-256 before every start. The catalogue is read only when "Check for
  updates" is on.
- The installers carry the plugins for the engines that ship with the app, and install them at
  the first start.

## Security
- Engines that accept a read-only transaction or session and write anyway are recognised and get
  no read-only mode or agents: RisingWave, Materialize, CrateDB, TiDB, SingleStore, Databend and
  GreptimeDB. After a read-only connection opens, the core reads the server's session mode back,
  and refuses the connection if it is still writable.
- In read-only work, ClickHouse's table functions that read files, URLs, buckets or other
  servers are refused, and so are Trino's and Presto's pass-through queries to the database
  behind a catalog.
- The guard asks first before each new language's destructive commands. Examples: dropping a
  collection, `FLUSHALL`, `DETACH DELETE`, `INSERT OVERWRITE`, a search index `DELETE`, and
  ClickHouse's `ALTER` statements that drop, move or replace a partition, set a TTL, or change
  every row.

## Fixes
- When the app cannot start (for example, a local store a development build left half-migrated),
  it shows a dialog that names the file and offers to start over with a new store. The old file
  is kept beside it. Before, the app closed without a word.
- An internal error (a panic) in the app or in `spelaiondb mcp` now ends that operation with an
  error. Before, a tab could wait for ever, and an agent's call never got an answer. The log says
  where it happened, without the values involved.
- A result whose statement failed or was stopped midway no longer says "(loading)" after the run
  has ended.
- A test of the CLI's MCP server no longer fails on a Windows that is not in English.

## Installing
- **Windows:** `SpelaionDB_0.10.0_x64-setup.exe` installs for the current user; an MSI is also
  available. Installers are not signed, so SmartScreen may warn.
- **macOS:** choose the Apple Silicon or Intel DMG. The app is not notarized; use right-click →
  Open the first time.
- **Linux:** choose the DEB, RPM or AppImage. Only the AppImage updates itself.
- **CLI / MCP server:** the `spelaiondb-*` archives contain the CLI binary and the engine plugins
  next to it.

Existing installations can update from the app's update notice. The first start after updating
takes a little longer while the app installs its plugins.
