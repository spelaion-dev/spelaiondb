SpelaionDB 0.9.0 is about administering a database without leaving the app: backups and
restores, structure editing with forms, ER diagrams, users and privileges, a view of what the
server is doing, search across a database, column masking, more ways to reach a server, and
charts.

## Administration
- Back up and restore PostgreSQL, MySQL and MariaDB with their own tools (`pg_dump`,
  `pg_restore`, `psql`, `mysqldump`, `mysql`), through the connection's tunnel. The password never
  appears on a command line or in a log, and a restore always asks first.
- Back up SQLite and DuckDB with their own commands, and run an `.sql` file against any
  connection, with progress and cancel.
- Create a table with a form (columns, primary key, foreign keys and indexes), and edit a table's
  columns with one: each change is a reviewed script, and SQLite rebuilds the table for you.
- Edit a view's, function's or procedure's source in the editor, and run a routine with a
  parameter form.
- Create, lock and drop roles, users and logins from the explorer; the new password is kept out
  of the SQL shown. Grant and revoke privileges from an account's menu (column privileges,
  PostgreSQL default privileges and SQL Server contained users included), and see what an
  account has.
- Watch the server: locks and who blocks whom, server settings and variables, and a table's
  sizes and row estimate.

## Exploring data
- ER diagrams of a schema, chosen tables or one table's neighbours, exported as PNG, SVG,
  Mermaid or DBML.
- Search across a database: names from the explorer's catalog, and a value in the tables you
  choose, always bound as a parameter and cancellable.
- Draw bar, line and pie charts from a result, and save them as PNG or SVG.
- The cell panel previews images, pretty-prints XML, saves or loads a value as a file, shows
  geometry values on a map (tiles only from a server you choose), and picks dates and times,
  allowed values and referenced rows.
- Bulk edits of a selection in table data, with undo and redo of pending edits.

## Security
- Column masking: mask chosen columns everywhere results leave the core (the grid, copies,
  exports, the MCP server), and reveal one cell on request. Set your own patterns in Settings,
  and a connection type's masked columns in its editor. Masking follows the table column a
  result reads, so an alias does not unmask it.
- A connection marked Read-only now also refuses writes typed in the editor on PostgreSQL,
  MySQL, MariaDB and SQL Server.
- Every password saved to the system keychain is checked, and the editor and the connection test
  say when none is stored.
- Agents' reads on PostgreSQL refuse functions that run SQL given as text and Unicode-escaped
  names, and their reads and writes on MySQL and MariaDB follow the session's `sql_mode`.

## Connections and network
- Reach databases through AWS SSM Session Manager, alone or before SSH hops.
- Share a cluster's Kubernetes settings between connections with Kubernetes network profiles.
- A running MCP server applies changes to its connections at the next call, without a restart,
  and replaces a lost database session instead of failing until the AI client restarts it.
- SSH asks each server first for the host key types `known_hosts` pins for it, and taking time
  to compare a fingerprint no longer makes the tunnel time out.

## The app
- A new sigma icon, release notes shown before installing an update, more compact result grids
  and connection folders, and a user guide split out of the README.
- On Linux: clipboard import and Paste connection, file dialogs over the app window, and Flatpak
  and Snap installs of DBeaver, Beekeeper Studio and MySQL Workbench found when importing.
  Updates install from the app only when it runs as an AppImage.

## Fixes
- Query results are paged only when every page can be fetched exactly, with keyset pages over the
  table's primary key, so the grid never shows a row twice or misses one. It also scrolls past
  about 1.4 million rows.
- Grid edits are written only where their rows were read, and a column filter can no longer move
  pending edits to other rows.
- Quitting or opening another folder asks first about unapplied row edits and running queries;
  closing a tab with an open transaction lists it once.
- The editor runs as one statement what the engine reads as one: MySQL and MariaDB dumps keep
  their views and triggers, PostgreSQL `BEGIN ATOMIC` bodies stay whole, and a SQL Server script
  that declares a variable runs in one batch. SQL Server asks before a DROP, TRUNCATE or DELETE
  that follows another statement without a semicolon.
- Commit, Rollback and the auto-commit switch answer right after a run; a cancel still on its way
  no longer stops the next run; DuckDB and SQLite stop statements cancelled before they start.
- Trusting a repository while moving a connection no longer loses the trust; a preference changed
  while another one is saving is no longer ignored; a second question of the same kind waits
  instead of replacing the first.
- MySQL and MariaDB results no longer fail on a zero date after the first 10,000 rows; SQL Server
  keeps the seventh digit of its date and time values, and the literals the core writes mean the
  same under every login language.
- Copying a single cell copies its value alone, without a line break after it.
- PostgreSQL refuses `COPY … FROM STDIN` typed in the editor instead of losing the connection, and
  remote SQLite refuses a `sqlite3` shell command written after a comment line.

## Installing
- **Windows:** `SpelaionDB_0.9.0_x64-setup.exe` installs for the current user; an MSI is also
  available. Installers are not signed, so SmartScreen may warn.
- **macOS:** choose the Apple Silicon or Intel DMG. The app is not notarized; use right-click →
  Open the first time.
- **Linux:** choose the DEB, RPM or AppImage. Only the AppImage updates itself.
- **CLI / MCP server:** the `spelaiondb-*` archives contain the CLI binary.

Existing installations can update from the app's update notice.
