SpelaionDB 0.14.0 is about looking finished: one icon set, one set of design tokens behind every
style, a grouped editor menu, shortcuts written the same way everywhere, buttons named by what they
do, and an import that shows what each client has before you choose.

## A finished look
- **One icon set.** Every icon is drawn by Lucide through one component, in place of hand-drawn
  icons and text characters (×, ▸, ↻, ★): the activity bar, tabs, the explorer, the editor's
  action column, the result grid (its sort arrows too), the connection test log and the dialogs.
- **Design tokens everywhere.** The whole stylesheet, the result grid included, takes its colors,
  sizes, radii, shadows and fonts from the theme's tokens, so light and dark (and the interface
  size) agree in every corner.
- **The result grid follows the theme.** Its fonts and highlights come from the theme, and edited,
  found and deleted cells keep a readable contrast in dark mode (at least 4.5:1). The cell editor
  follows the grid's font size.
- **Thin, themed scrollbars** in every scrolling region, the result grid included; they widen
  under the pointer.
- **Soft connection-type badges:** only Production stays solid.

## Menus, shortcuts and the palette
- **A grouped editor menu.** Right-clicking the SQL editor shows Run, Explain, the clipboard,
  Format and comments first, with submenus for running, selection, inserting, going to, view and
  session.
- **Shortcuts in words from one table.** Menus, tooltips and the palette write each shortcut the
  same way, in your language's key names, and with ⌘ ⌥ ⇧ on macOS. The explorer's menus show their
  shortcuts beside each item.
- **Change any shortcut.** Settings › Keyboard shortcuts lists every command with its keys and a
  search; any shortcut can be changed, removed or reset, and clashes are refused. Keys that
  dialogs rely on (Enter, Escape, Tab) cannot be taken (ADR-064).
- **More in the command palette.** The explorer's actions on schemas, tables, views, routines,
  sequences and triggers (rename, drop, duplicate, generate DDL, copy name…) run from the
  palette through the same dialogs, and the result grid's selection can be copied (TSV, CSV, JSON,
  Markdown, an IN list, INSERT or UPDATE statements…) or exported from it.

## Buttons that say what they do
- Confirmation buttons are named by their action: "Delete connection", "Drop …?", and the SSH
  prompts' "Unlock key", "Sign in", "Sign in to proxy" or "Send code".
- Deleting a saved query, a network profile or a connection type asks first, in one dialog; a
  network profile still in use lists the connections that use it.
- Cancelling running work is a secondary Cancel button, named the same everywhere; the MCP
  activity's "Clear log…" is no longer red until you confirm.

## Importing connections
- **See what each client has.** The sidebar's Add button opens a list of the clients you can
  import from, each saying how many connections it found on this computer, or that it needs a
  file or is encrypted. Counting opens no saved password and asks no keychain.
- **Startup commands come along.** Other clients' startup commands (TablePlus's bootstrap
  commands, DBeaver's bootstrap queries) become the connection's session setup, and DBeaver's
  default schema and isolation level come too. The preview shows every imported statement before
  you save; on a read-only or Production-like connection each one must pass the same check as a
  setup you type, and one that does not is left out and listed.

## Results and the map
- **Follow foreign keys from a query's result** when it reads one table, as from that table's
  own data: links, Ctrl+Enter, the menu and the references panel.
- **SQL Server geometry and geography on the map**, and well-known text (`POINT (1 2)`…) in any
  text column. Geography's latitude-first order is read from the column's type, which the SQL
  Server plugin 0.1.1 now reports.

## Fixes
- **Edits stay tied to the table that produced the rows.** A query's result and a table's data
  page are editable only when the core knows which table they came from, and an edit to a table
  that was dropped and recreated since is refused instead of written to the new one.
- **psql meta-commands in PostgreSQL scripts.** A meta-command line (`\echo it's`) no longer hides
  the next statement's placeholder, and a `\copy … from stdin;` line is refused before anything is
  sent to the server. A `COPY` after a space outside ASCII is read as the splitter reads it.
- A running tab's state change re-renders only that tab, not the whole window.
- `url` 2.5.9 (RUSTSEC-2026-0592).

## Agents
- `explain_query` names the engines with structured plans from the core's own capabilities.
- `list_objects`, `search_schema` and `describe_table` answers stop within about 60,000
  characters; a cut answer says how many entries were left out and which argument asks for the
  rest, in its text and its structured content.

## Under the hood
- ADR-063 decides how the installers will be signed: Apple Developer ID and notarization for macOS
  first, then SignPath for Windows; the code signing policy is published in
  `docs/code-signing-policy.md`.
- The core's and the configuration crate's integration tests are linked into one binary each,
  halving a test build's size on disk; `scripts/clean-target.sh` cleans old build folders.
- The Windows smoke test waits for the webview's page and for running transitions, and three
  intermittent steps were made steady.

## Plugins
- SQL Server: plugin 0.1.1 reports geometry, geography and hierarchyid columns by their type.
