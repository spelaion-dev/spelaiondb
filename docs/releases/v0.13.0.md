SpelaionDB 0.13.0 is about not misleading you: what the app and its agents show is what is
really happening. A result cut short says so, a run says where it is, a tunnel says when it is
still opening, and a cancel pressed at any moment stops the statement it was meant for.

## What you see is what is happening
- **A result cut short says so.** When a cancel, an error or a timeout stops a query before its
  last row, the result says it is partial and why, instead of looking whole.
- **Where a run is.** The status line says when a script is running, paused at a statement
  ("Paused at statement 3") or cancelling, and Cancel comes back only once the cancel is done.
- **Query progress you can cancel.** The results panel shows a running query's elapsed time and
  a Cancel button, and the toolbar's Refresh runs it again.
- **Tunnels have an opening state.** A tunnel is shown as opening until every hop is up, and an
  opening whose earlier hop is lost fails instead of being reported as up.
- **Transactions.** An editor tab's transaction is one state the core owns, so the tab, the
  toolbar and closing the tab always agree on whether one is open.
- **Plugins and updates.** A plugin download shows wherever the plugin is shown: in Settings, in
  the "add connection" picker and under a connection that could not open. An update's download
  shows its progress, and a failed install can be tried again without checking again.
- Statuses that used to travel as text are typed, and a value the app does not know is never read
  as one it knows.

## Agents
- **Why a call failed, as a stable code.** Every refusal or failure of the MCP server carries a
  code an agent can act on (`session_lost`, `read_only`, `refused_by_guard`, `plugin_missing`,
  `timed_out`…) and whether running the same call again may work. `list_connections` gives each
  connection's access and why it is read-only. The codes are kept in the Activity tab's audit.

## Fixes
- **A cancel pressed the instant Run is pressed stops the statement.** Before, it could reach
  the driver before the statement was numbered and be lost, and the statement ran to its end.
  The MySQL plugin 0.1.6 carries the plugin side of the fix.
- **A bound value ending in a backslash stays a value.** On ClickHouse, Databend, Spanner, Hive
  and TDengine, where a backslash escapes a quote, such a value ended its literal early and
  could change the statement that ran.
- **Pasting a script that ends in a no-break space** (or another space outside ASCII) no longer
  makes the app fail.
- The result grid's footer stays in place, so selecting a cell no longer shrinks the grid under
  the pointer.

## Under the hood
- Every lifecycle in the app is one explicit state type owned by the core (ADR-060): jobs share
  one cancel and one ending, the desktop's running work is kept in one registry, dialogs share
  one "preview, then apply", and the app's own lifecycle (quitting, switching folder, installing
  an update) is explicit.
- Property tests generate inputs for the SQL splitters, the placeholder scanner, the barriers and
  the readers of untrusted files.
- The Windows smoke test runs in CI, and pull requests into `dev` merge through a merge queue.
