SpelaionDB 0.17.0 shows more at once. Put two tabs side by side, move a tab's results or a
connection into a window of its own, and open several folders in one window, each with its own
trust. Save an ER diagram with the tables where you put them, notes and colored groups. Watch a
server's sessions and throughput live. A PostgreSQL connection now shows every database it may
open, and a tab chooses which one it runs on.

## Split view and windows
- **Split right and Split down** in a tab's menu put two tabs on screen together, each with its
  own session, results and connection row. The separator resizes with the pointer or the arrow
  keys, and closing a pane's tab goes back to one pane.
- **A tab's results in a window of their own:** the window reads the same stored results, so
  nothing is run or fetched again, and Re-attach results brings them back to the tab.
- **A connection in its own window**, which starts with a new query on it. Closing it asks about
  its own tabs only and closes only its own sessions (ADR-083).
- **SSH questions go to the window that asked:** an unknown host or a key's passphrase for a
  backup, import, copy or comparison is asked in the window it was started from, never in every
  window.

## Several folders in one window
- **Open more than one folder at once.** Each folder keeps its own configuration, sessions and
  trust, and the sidebar shows one group per folder.
- **A tab belongs to its connection's folder**, so a folder's history and saved queries stay
  with it, and every open folder's are listed.
- **A connection is identified by its folder and its id everywhere.** Two repositories'
  `prod/orders` are told apart in the explorer, the windows and the audit log, which now records
  the folder.
- **A personal connection takes from the open folders only what tightens it.** A folder can make
  it stricter, never looser, and changing which folders a connection reads needs an owner's
  review.
- **The MCP page lists connections and activity by folder.** Each connection is decided as a
  server started in that folder would decide it, and the read-only override is written to the
  connection's own folder. The MCP server itself still serves one folder.

## ER diagrams
- **Save a diagram** under a name and open it again from the command palette. What is saved is
  the arrangement: where each table was put, notes, colored groups and the display options, as
  local data. The catalog is never stored in it (ADR-084).
- **Drag tables, notes and groups**, and the relations are routed again around them. Opening a
  saved diagram reads the catalog again: new tables are marked new, and tables that are gone are
  drawn dashed where they were. PNG and SVG exports include the notes and groups.
- **Large schemas read faster.** A schema's tables and keys are read in one catalog call where
  the engine has it (plugin protocol 1.4), which halves the time on a 200-table SQLite schema and
  helps most over slow tunnels. PostgreSQL's plugin reads it from its 0.1.9.

## Live server dashboards
- **A Dashboard view in the process monitor**, next to Processes, Locks and Settings, draws
  sessions (connected, active, waiting), transactions per second, logical reads and log bytes
  written over time, for PostgreSQL, MySQL, MariaDB and SQL Server.
- It reads one statement every 5 seconds while it is shown, each classified as a read before it
  runs, and nothing while it is hidden. It keeps the last 30 minutes in memory only.

## PostgreSQL databases
- **The explorer shows a connection's databases**, each with its schemas and extensions, when
  its connection file names the other databases it opens (ADR-074). Another database opens a
  session of its own when its row is first expanded.
- **A tab chooses its database** from the toolbar and remembers it. Choosing another one
  disconnects the tab and connects it to that database; nothing is run again.
- **Backup, restore, data search, ER diagrams and privileges** work on the database they were
  opened from.

## Scripts and the guard
- **A failed statement no longer ends a PostgreSQL transaction**, when you turn it on in
  Settings > Scripts. The core sets a savepoint of its own before each statement and rolls back
  to it when the statement fails, so Commit keeps the rest. Your own `SAVEPOINT`s keep working
  (ADR-086).
- **MySQL, MariaDB and SQL Server scripts are read by one lexical scanner each**: `DELIMITER`,
  executable comments and `sql_mode` on MySQL; nested comments, `GO` and `BEGIN … END` on SQL
  Server. The splitter, the highlighting and the guard can no longer disagree. Statements split
  exactly as before.

## Fixes
- **PuTTY keys (.ppk) with a passphrase are asked for it.** The tunnel failed with "reading …"
  instead. Versions 2 and 3, RSA and Ed25519, with the same three attempts as an OpenSSH key, and
  Pageant is offered the right key.
- **The chart toggle no longer looks like a result tab when it is on.** The chart and transpose
  toggles are rounded on every corner, with the accent on its soft background when pressed.

## Maps
- **OpenStreetMap in one click:** Settings > Map > Use OpenStreetMap fills the server and its
  attribution and turns tiles on, and says what each tile tells the server. Tiles stay off until
  you turn them on.
- **Tiles are fetched by the core**, never by the web view, under OpenStreetMap's tile policy: a
  disk cache that honours the server's caching headers, two requests at a time, at most 300 per
  map, one stable User-Agent and no referrer or cookies (ADR-085).

## Under the hood
- The smoke tests wait until a tab can start a run before pressing Run; pressing it earlier made
  the Linux smoke's SQL Server step time out once.
