SpelaionDB 0.18.0 keeps the work you repeat. Write an investigation as a SQL notebook, with
the reasoning between the queries and one cell reading another's result. Save an export, an
import, a backup or a script run as a task and run it again from the app or the command line.
Take your settings and personal connections to another computer, passwords included, in a file
only your password opens. And remember an SSH key's passphrase in the system keychain, so a
tunnel stops asking for it every time.

## SQL notebooks
- **A notebook is a Markdown file** with named SQL cells and text between them. GitHub and any
  editor show it as a document, and a diff shows the SQL and the text that changed (ADR-087).
- **One cell can use another's result:** `{{name}}` in a cell becomes a CTE of that cell's
  query, checked by the guard and the read-only barrier like any other statement.
- **Run a cell or Run all**, top to bottom, stopping at the first error with a summary. Each cell
  shows its results inline, with a chart.
- **Opening a notebook never runs or connects anything.** Results are never written into the
  file, so nothing a query returned ends up in git; Export as HTML writes them on purpose.
- Notebook tabs come back after a restart, like file tabs.

## Saved tasks
- **Save as task…** in the export, import, backup and restore, and Run SQL file dialogs keeps
  the run's options under a name. A task never stores a password: saving refuses one that holds
  the connection's password or a password in a backup tool's arguments (ADR-089).
- **A Tasks view** in the activity bar runs, edits, duplicates and deletes tasks, in folders, with
  every run's log (secrets masked).
- **`spelaiondb task run NAME`** runs the same task from the command line, so your own scheduler
  (cron, Task Scheduler) can start it. Nothing runs on its own inside the app. The command line
  never asks: a run that would ask by hand needs `--yes`.

## Settings that move with you
- **Export and import your personal settings** in one file, checked whole before anything
  changes.
- **Move your personal connections to another computer** in a file encrypted with your password
  (Argon2id and AES-256-GCM). Their passwords go back into the new computer's keychain, never into
  a file. A wrong password or a changed file fails cleanly and writes nothing, and an imported
  connection can never read a password the new computer already keeps (ADR-088).
- **A log viewer** in Settings, by level, with export; every entry is scrubbed of secrets.
- **Settings reach every window.** A preference changed in one window, or a settings file
  imported, shows at once in the other open windows, and a window opened earlier no longer saves
  an old value back.

## SSH
- **Remember an SSH key's passphrase** in the system keychain: a box on the passphrase question,
  off by default. Only a passphrase that opened the key is kept, one entry per key file; one that
  no longer works is forgotten and you are asked again, and Forget in the SSH settings removes it.
  Pageant and the OpenSSH agent are still tried first (ADR-090).
- **A changed team `known_hosts` is always reviewed.** A new session made from an open one used
  to reuse the old resolution after the team changed a host key; now it goes through the review.

## Scripts and the guard
- **Client commands in scripts:** `@set`, `@unset` and `@echo` in the editor's script runs, and
  `@include` to read another `.sql` file of the script's own folder tree (only `.sql`, never
  outside the tree, at most 8 levels and 100 files). A line starting with `@` is never sent to
  the server, and agents and read-only connections refuse it (ADR-078).
- **Every SQL dialect is read by one lexical scanner:** SQLite, DuckDB, Oracle, ClickHouse,
  Trino, Hive, Spanner, Databend, TDengine and CQL join PostgreSQL, MySQL and SQL Server, and the
  SQLite-over-SSH check reads SQLite's. Statements split exactly as before, checked against the
  old code on 300,000 generated scripts per dialect (ADR-065).
- **A CQL statement starting with `BEGIN` that is not a batch no longer crashes the app.** The
  guard read it as a batch forever and overflowed the stack.

## MCP
- **The Activity tab says more:** the database each statement ran in, whether a call was a read,
  a write or a catalog look, and **Open in editor** to put a logged statement in a new tab on its
  connection, without running it. Both exports gain a database column.

## Fixes
- **OpenStreetMap can be turned off again.** Tiles turned off in one window kept showing, and
  were saved back on, in a connection's or a results window.
- **Map settings keep what you are typing** when an earlier save of the same form lands.
- **A Run pressed while a tab connects** or lists its databases waits and runs once, and says
  why when it cannot, instead of doing nothing.

## Under the hood
- Two smoke steps that failed now and then wait on what the core reports, and a test's leftover
  temporary folder no longer breaks a later run.
