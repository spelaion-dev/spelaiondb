SpelaionDB 0.11.0 is about keeping up with you: results that stay while you try a variant, a
Run button that says what it will send, sorts and filters you do not retype, a way from the SQL
to the table it names, your own snippets and variables, values shown the way you read them, and
ways through results of a million rows.

## Running queries
- **Run says what it will run.** The Run button reads "Run statement", "Run selection" or "Run
  script" as the cursor moves. When a selection holds several statements, a picker asks which to
  run (keys 1–9, several, or all). **Run from the cursor to the end** with Ctrl+Alt+Enter.
- **Results you can keep.** Run into a new result tab (Alt+Enter) instead of replacing the
  results; pin a result so no run replaces it; rename a result tab (a statement that starts with
  a `--` comment names it); run one result's query again into its own tab. A setting limits how
  many result tabs an editor tab keeps.
- **Variables and remembered parameters.** `${name}` variables, set for a tab or for a
  connection in a Variables dialog, are written into the statement before it runs, only in code
  (never inside strings or comments), and the core refuses a value that would end the statement
  or start another. Each `:name` parameter offers its last value.
- **Your own snippets** in Settings → Snippets, expanded with Tab and its fields like the
  built-in ones (one can replace a built-in by name), and a template for new scripts.
- **From SQL to the object.** Ctrl+click a table name (or F12) opens its columns; hover a table
  for its columns and types, a column for its type and comment; an outline panel of the script's
  statements (Ctrl+Shift+O), and Alt+PageDown / Alt+PageUp to the next or previous statement.

## Results
- **Sort by several columns.** Shift+click a header adds it to the sort, and the headers show
  each key's order and position. A table data tab sorts on the server, and a paged query is read
  again from the server in the sort's order.
- **Filters you do not retype.** The table data tab's filter box remembers each table's filters
  and completes column names; save a filter as the table's default; column filters can match
  any or all, and match case; pick a filter value from the column's most frequent ones (never a
  masked column's).
- **Values shown the way you read them.** Date, time, timestamp and number formats (a few
  presets or a pattern), a display time zone, binary as hex, text or base64, values colored by
  type, a column's type and comment in its header, and a result font size of its own. Copies,
  exports and filters keep the database's own text unless you choose "Copy as displayed".
- **Grouping panel.** Counts and percents per group of one or more columns, "duplicates only",
  and a click on a group filters the grid to its rows.
- **Move through big results.** A transposed view of the current or selected rows, a pagination
  bar (first, previous, next, last, page N) on table data tabs and paged queries, go to row
  (Ctrl+G), and Load every row, which says how many rows and roughly how much memory first.
- **Copy the way you need it.** "Copy special…" chooses the delimiter, quote character, row
  delimiter, NULL text, header and row numbers, and remembers them; "Copy as SQL UPDATE" writes
  one UPDATE per row by the table's primary key, only when the result comes from one table with
  its whole key, and never from a masked value.
- A result tab's name can be taken off again ("Reset name"), giving back its comment's name.
- Start editing a cell by typing, select rows that are not next to each other with Ctrl+click,
  refresh a result from the grid, and format or wrap JSON in the cell viewer.

## The app
- **Interface size** (90 % to 150 %) in Settings → Appearance, and editor zoom with Ctrl+= / − / 0.
- **Engine logos** for the engines added in 0.10 (Trino, Presto, Spanner, Neo4j, Hive, Spark,
  Elasticsearch, OpenSearch, Solr, Meilisearch and more), each from a licensed icon set; an
  engine without a licensed mark shows a neutral icon.
- **A Content Security Policy** on the app's window: no script but the app's own can run in it.
- New query tabs opened from a connection connect at once, and the editor's occurrence shortcuts
  select inside longer names.

## Fixes
- Query pages are keyed only by primary keys the engine enforces unique, so a ClickHouse sorting
  key or a connector's key can no longer make a page skip a row; on SQL Server, pages over a
  `varchar` key follow its collation (before, hyphens and apostrophes could hide rows).
- Several table edits at once and imports are refused on servers that accept transactions and
  ignore them (GreptimeDB, CrateDB), instead of leaving half of them applied.
- Cancelling "Run SQL file…" set to continue on errors stops the rest of the file.
- Ctrl+Enter runs a MySQL procedure or trigger written under `DELIMITER` whole, instead of as
  its pieces.
- Filtering the grid to a group keeps exactly that group's rows, and says when that makes the
  other column filters match case.
- At 150 % the grid no longer cuts off the last rows of results near a million rows.
- Two quick clicks on a table data header sort as the second click asked.
- The outline of a row revealed in the explorer goes away again.
